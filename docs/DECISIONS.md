# Decisions

Choices made where `docs/GAME_SPEC.md` is silent or allows more than one option. Each entry says what was chosen, why, and what it would take to change. Newest at the bottom.

| ID | Decision | Why | To change |
| --- | --- | --- | --- |
| D-001 | The GitHub repo keeps the owner's own name, which contains the source franchise's abbreviation, so that name is never written inside the repo (the blocklist catches it); the game, every file, every name inside the repo and the store page use **Skyspire** names only. | Section 3: the feel is not protected, the names are. The repo name is not shipped. | Rename the repo in GitHub settings; nothing in the repo spells it. |
| D-002 | Modules reference each other with Roblox Instance paths (`script.Parent.x`, `ReplicatedStorage.Shared.x`). Lune tests load the same files through a virtual DataModel (`tests/_harness/`) that resolves those paths from `src/`. | Instance paths are guaranteed in every Roblox context and every Rojo version; string requires are newer and their `init.luau` semantics differ between Lune and Roblox. The harness keeps one copy of the code testable in both. | Switch to string requires once Roblox and Rojo both ship them as stable; the harness can resolve those too. |
| D-003 | Choreo clip data is plain numbers: joint offsets as `{pos = {x, y, z}, rot = {x, y, z}}` in studs and degrees. The Choreo runtime compiles them to CFrames once at load. | Plain tables are testable in Lune (no `CFrame` at module load), diffable in git, and writable by the PoseEditor plugin. | Add a `cframe` field to `JointKey` and teach the compiler to prefer it. |
| D-004 | Phase 0 has zero Wally packages. Signal, Spring, Easing, Verlet, Rng and the schema checker (`Check.luau`) live in `src/shared/util/`. `wally.toml` lists the planned packages commented out. | The Phase 0 gate must be reproducible from a clean clone with no registry access; the utilities are each under 150 lines. | Uncomment the package in `wally.toml`, `wally install`, add `Packages` to the project JSON, replace the util. |
| D-005 | Places are built artifacts: `places/*.project.json` holds the static world (field, ceiling, lighting) and `src/server/world/` builds the rest (rim, pillars, clouds, spawn tables) from data at server start. `.rbxl` files are gitignored and produced by `tools/build-places.sh` / CI. | A place that is regenerated from git can never drift from the data tables, and Git LFS is not needed until hand-built art arrives. | When hand-authored floors arrive (Phase 3), commit them under LFS and remove them from `.gitignore`. |
| D-006 | Entity state that the HUD needs (HP, MaxHP, Gauge, MaxGauge, State, Name) replicates as Attributes on the entity Model, written only by the server. Remotes carry events (actions, hits, deaths, telegraphs), never state snapshots. | Attributes replicate automatically, are cheap, and cannot be written by a client; it keeps the remote schema small. | Add an `EntityState` remote if attribute replication latency is ever measured above 100 ms. |
| D-007 | UI uses a hand-rolled component library (`src/client/ui/lib/`): `el(className, props, children)` plus a tiny state cell. Fusion is not used in Phase 0. | No package dependencies (D-004) and the Phase 0 HUD is small. The library's surface is designed so Fusion could replace it at the diegetic-menu phase. | Phase 2: evaluate Fusion for the diegetic menu; record the result here. |
| D-008 | The network layer is a typed wrapper of our own (`src/shared/net/Net.luau`) over `RemoteEvent` / `UnreliableRemoteEvent` / `RemoteFunction`, with every payload validated by `Check.luau` schemas on the server, per-remote rate limits, and a kick on sustained abuse. ByteNet is not used. | Section 17 allows either; the wrapper is under 300 lines and needs no package. | Phase 1: if bandwidth profiling shows the need, swap the transport under the same API. |
| D-009 | Phase 0 rigs: the player is the default R15 character with anime proportions from `rigs.luau` applied through Humanoid scale values and listed in `PLACEHOLDERS.md`. Enemy rigs are part-built stand-ins assembled by `RigBuilder` from `rigs.luau` (joint list, rest pose, Motor6Ds) and tagged `Placeholder`. | The custom mesh rig needs Blender and a Studio upload (a Studio task); the Choreo system only needs Motor6D names and rest poses, which the data defines. | Upload the mesh rigs, add their ids to `assets.luau`, point `rigs.luau` at them. |
| D-010 | Server hit detection samples the weapon's path at 60 Hz during each damage window and runs `workspace:Spherecast` between successive samples (a swept capsule approximated by spheres). The 150 ms lag allowance is a time rewind: a requested Art or basic swing starts its server timeline at the request's `clientTime` (stamped with `workspace:GetServerTimeNow()`, the clock the server reads), clamped by `CombatService.runStartOf(clientTime, receipt, freeAt)` into `[max(receipt - lagAllowance, min(freeAt, receipt)), receipt]`, where `freeAt` is the fighter's `lockUntil` read before the new action replaces it. Windows, lock, `ActionStarted.serverTime` and the basic chain clock run from that start, so a rewound action never overlaps the post-motion, stagger or swing before it; a request accepted inside `artRequestTolerance`, or one that cuts a basic swing still in flight, starts at receipt. Code callers (`beginArt`, `beginBasic`) start at receipt. The facing check is a separate cosine slack (`combat.facingTolerance`). | Roblox has no capsule sweep primitive; spherecasts along the path are cheap and deterministic on the server. Section 6 asks for a 150 ms lag allowance on the sweep; section 17 says an Art cannot be requested more often than its clip allows, so the rewind is floored at the previous lock's end (unbounded, an early stamp fit about 19% more Arts). | Replace `HitSweep.luau` with a shapecast when Roblox ships one; tune `lagAllowance` in `combat.luau`. |
| D-011 | Clip clocks sync on `workspace:GetServerTimeNow()`; there is no custom time-sync remote in Phase 0. | The engine clock is already synchronized to within a few ms, which is inside the 150 ms lag allowance. | Add `TimeSync` to `Net.luau` if the measured drift ever exceeds 50 ms. |
| D-012 | Enemies keep a `Humanoid` for `MoveTo` and pathfinding only; `Humanoid.Health` is pinned to a constant and ignored. Real HP lives in `EnemyService` and replicates by attribute (D-006). | Section 16 asks for `Humanoid:MoveTo` on simple mobs; section 6 says the server owns HP, so the engine's health must not be a second source of truth. | None planned. |
| D-013 | The 400-stud Playground field is a flat disc at Y = 0 with the rim at radius 200 and the ceiling at Y = 350, matching the spec's floor anatomy at one-seventh scale. | Section 20 asks for a 400-stud field with a rim and a ceiling; the ceiling height is the real one so the look-up reads correctly. | Edit `playground.luau`. |
| D-014 | The naming blocklist is the single file `tools/naming/blocklist.luau`: the only file in the repo allowed to hold source-franchise strings. Generic English entries (short words and common nouns) match whole words; every other entry matches as a substring so plurals and compounds are caught. `tools/validators/naming.luau` scans every text file except `docs/GAME_SPEC.md` and the blocklist itself. | Section 3 forbids the names everywhere, so the check has to be repo-wide and the list has to live somewhere Rojo never ships (`tools/` is outside every project JSON). | Edit the list; add a `wholeWord` flag to an entry to change how it matches. |
| D-015 | Clip authoring is scoped by phase: `src/shared/data/scope.luau` holds `phase` and the Art, enemy, boss and rig ids whose clips the current phase must ship (Phase 0: One-Handed Sword Horizontal, Vertical, Rising Arc and Sharp Nail; Frenzy Boar and Kobold Axeman; no boss; rigs PlayerR15, Boar, Kobold). The clips validator fails on a missing clip for an in-scope Art, enemy attack or boss attack and folds every other missing clip into one summary warning counted once per clip id. A clip file that exists is always validated in full. Without `scope.luau` every row is in scope and the missing table is itself a problem, so nothing is ever hidden; `tools/validators/scope.luau` checks that every id resolves and nothing is listed twice. | The data tables hold floors 1 to 10 and every weapon line on purpose so later phases are data work, but CI must be green on what the phase ships; the flat "missing" report (160 lines once boss attacks are cross-checked) hid real problems. | Raise `phase` and add ids to `scope.luau` when a phase starts; the validator then demands their clips. Delete `scope.luau` to drop scoping. |
| D-016 | The player rig's root Motor6D is named `Root` (the live R15 name, in `LowerTorso`), in `rigs.luau`, in every player clip and in `LocomotionState`. The clip root-motion key stays `__root` in `ClipSampler`. | The Choreo runtime and the server pose solver look Motor6Ds up by name; an `R6`-style `RootJoint` key is silently ignored on a real R15 character, which would drop the torso drop and lean of every clip. | Rename in `rigs.luau` and run `sed` over `src/shared/clips`; the clips validator checks every joint name against the rig. |
| D-017 | Data modules with many rows (`arts`, `weapons`, `armor`, `enemies`, `bosses`, `loot`, `floors`) keep them under `Module.rows` with `byId(id)` and `list()` functions, and return clones from `list()` so callers cannot corrupt the table. Validators read `rows` first and fall back to the module table. | One shape for every table lets the cross-table validators (clips, floors, playground, palette-usage) stay generic. | Add the convention to a new table and its validator. |
| D-018 | Weapons a boss wields are `weapons.luau` rows flagged `bossOnly = true` (never dropped, never equipped by a player); Khagan's Greataxe is the floor 7 Last Attack Bonus and a Legendary. The floors 2 to 10 Last Attack Bonus items without rows yet are listed in `Bosses.pendingLab` so the bosses validator can enforce them when the rows land. | Section 12 lists the boss weapons as loot or as the boss's own tool; one row type for both keeps the loot roll honest. | Remove an id from `pendingLab` when its row exists. |
| D-019 | Enemy target switching has hysteresis: a threat holder takes over only when its threat is at least `ai.perception.threatSwitchMargin` (1.25) times the current target's. | Section 6 says "whoever has the highest threat"; without a margin two players trading hits make the enemy spin between them every tick. | Set the margin to 1 to follow the sentence literally. |
| D-020 | Section 8 startup values below 0.25 s (Rapier Linear 0.22, Katana Iai Cut 0.2, Dagger Rapid Bite 0.2, Twin Fang Cross Block 0.15) are kept verbatim. The 0.15 s start pose and 0.1 s activation hold of section 6 are compressed to fit when those clips are authored; the clips validator compares every clip to its row. | The Art table is the tuning the designer wrote down; the section 6 numbers are the default feel for the first weapon. | Raise a row's `startup` to 0.25 in `arts.luau`. |
| D-021 | Guard-archetype enemies carry a `ShieldBash` attack (no Guard Break, low damage) although section 9 describes the archetype as "raises shield (no attack)". | Every enemy row needs at least one attack for the AI, the telegraph validator and the clip cross-check to work; a guard pack that can never threaten reads as scenery. Phase 0 ships no Guard enemy. | Delete the `ShieldBash` row from the Guard archetype rows and let the Brute fallback brain skip attacking. |
| D-022 | Floors whose feel is not literally one of the generator kits map to the closest kit for lighting and rosters: 5, 10, 15 and 20 -> plains, 14 -> coast, 16 -> canyon, 17 -> savanna, 21 -> marsh, 22 -> forest, 24 -> volcanic, 25 -> ruin. Floor 1 is enforced as the warmest-lit floor (largest red-minus-blue tint; the lighting validator fails any biome that ties it). | Section 5 names more floors than section 7 names kits. | Edit `floors.luau`'s `kit` column and the lighting preset. |
| D-023 | Original Art names for the weapon lines section 8 leaves without a table: Martial Arts (Palm Strike, Crescent Kick, Falling Comet, Hundred Fists, Tempest Heel), Shield (Shield Bash, Rampart Slam, Bulwark Rush, Riposte Bash, Iron Meridian), Aegis Blade (Vow Strike, Oath Line, Unbroken Stance, Judgment Cross, Final Verdict). Preconditions follow the section 8 notes (Moving, Standing, Airborne, AfterParry). | The spec asks for five Arts per line; these names passed the blocklist and fit the section 4 vocabulary. | Rename rows in `arts.luau`; clip ids follow the row name. |
| D-024 | Phase 0 has no jump: Space is the dodge (section 6 lists no jump input) and the character's JumpPower is 0. Ledges still produce Fall and Land through the fall tracker. | A jump would add a third vertical state to the locomotion blend space before the IK layer exists. | Bind a jump in `input.luau` and restore JumpPower in `CharacterController`. |
| D-025 | Bindings the spec leaves open: gamepad Art hold on R1, slot 2 on Y, slots 3 and 4 on D-pad Up and Right, the quick-slot ring on D-pad Left; sprint is hold on keyboard and toggle on gamepad and touch; the touch layout adds a LOCK button to the five section 14 actions; a dodge with no move input is a backstep. | Lock-on is otherwise unreachable on a phone; the backstep is the anime read of an empty dodge. | Edit `input.luau`. |
| D-026 | Anti-cheat judges the horizontal plane only (falls and the kill volume own the vertical), weights a teleport by how far it exceeds the allowance (capped at `anticheat.teleportWeightCapFraction`, 0.5, of the kick threshold), needs at least two separate anomalies before a kick, sets the shadow flag at `anticheat.shadowFraction` (0.5) of the kick weight, and counts remote-abuse reports as weight-1 anomalies in the same window. Per-remote rate limits (requests per second and burst) live in `anticheat.remoteRates`, keyed by remote name; the world validator checks they cover exactly the client-to-server remotes. | Section 17: "never kick on a single anomaly" and the shadow flag before any ban. | Tune `world.luau` `anticheat`. |
| D-027 | Enemies and entities live in `workspace.Enemies` and `workspace.Entities`; the Playground rim (railing, pillars, clouds, kill volume) lives under `workspace.Playground`. The death system line is produced on the client from `EntityDied` (Player entities only), not sent as a `SystemLine` remote. | One folder per concern keeps `CollectionService` scans cheap; one producer for the line avoids a double announcement. | Move the folders in `world.luau`; move the line to the server in `EntityService` and delete the client branch. |
| D-028 | Dev tooling runs only in dev places: the Capture panel when `workspace` has `DevCapture = true`, the ClipLab when `ClipLab = true`. The PoseEditor is a Studio plugin (`tools/PoseEditor`) that saves clips through `tools/pose-server.luau` (a Lune HTTP server that writes the module, runs StyLua and the validators). Every dev number lives in `data/dev.luau`. | Clips are data modules in git, so the editor has to write source, not a binary; a local Lune server is the smallest bridge from Studio to the repo. | Replace the pose server with a Rojo plugin endpoint when one exists. |
| D-029 | The Playground loadout grants One-Handed Sword proficiency 150 so all four slice Arts (Horizontal, Vertical, Rising Arc, Sharp Nail) are usable for the gate recording; the server rejects an Art that is not in the fighter's quick slots (`NotSlotted`) as section 17 asks. | The gate clip needs every slice Art; the slot check closes the one validation section 17 names that the first pass skipped. | Edit `playground.luau` `loadout`. |
| D-030 | Art names are taken verbatim from the section 8 table, including the Katana rows (Tsujikaze, Gengetsu, Hiogi) that echo a source skill name. Hard rule 1 is defined by the section 3 and 4 forbidden-name list that `tools/naming/blocklist.luau` encodes, not by resemblance. | The spec names them itself, and it says never to re-ask what it answers; the blocklist is the one place the forbidden list lives. | Rename the rows in `arts.luau` (clip ids follow) and add the old names to the blocklist. |
| D-031 | A guard raise can parry only if the guard was down for at least `combat.parryRearmTime` (0.25 s) since its last release; a raise sooner than that still guards but cannot parry. | Section 6 defines the parry as a guard tap inside the 150 ms before a hit and is silent on repeated taps; without a re-arm, tapping guard as fast as the remote allows would turn every hit into a parry chance. | Set `parryRearmTime` to 0 in `combat.luau` to drop the rule. |
| D-032 | Blend envelopes reach the limbs through `choreo.luau` `blendEasing` (SineInOut); a handle's fade stays linear progress and root motion fades on the raw envelope. | Sections 10 and 21 forbid linear tweens on limbs, and the 0.2 s blend back to locomotion is a limb motion. SineInOut is symmetric, so an equal crossfade still sums to 1. | Change `blendEasing` in `choreo.luau` to any `Easing` name. |
| D-033 | Blend-space weights retargeted on one layer move by one shared fraction per frame: the largest mover travels `locomotion.weightBlendRate` per second, the rest in proportion, and every weight lands exactly on its target. | Independent constant-rate ramps let a layer's weight sum drop below 1, so a stop out of a diagonal or gait mix dipped the pose toward rest; an exponential approach never lands and settles about three times slower. | `Mixer.luau` `weightFractions`; tune `weightBlendRate` in `choreo.luau`. |
| D-034 | Anti-cheat speed checks spend the 150 ms lag budget once, not per sample: each player holds a lag credit of `maxSpeedStudsPerSecond` x `lagAllowance` studs. A sample is judged against the sprint cap over the interval plus any Art or Dodge grant plus the credit; distance past the allowance spends the credit and distance under it refills it, never above full. The credit is full at the start and after every sample reset (death, respawn, new character, lost root). | The spec names the 150 ms budget for hit distance only. Replication jitter does not accumulate, so an honest root travels at most the cap over the elapsed time plus one lag; a per-sample grant let a sustained walk at 1.6x the cap pass forever. | Tune `combat.luau` `lagAllowance` / `maxSpeedStudsPerSecond`; the arithmetic is `Rules.maxCredit` / `Rules.nextCredit`. |
| D-035 | Every death ducks Music, SFX and UI together by `combat.deathDuckDb` (40 dB) for `deathFreeze`, and the system line comes after the shatter: the dying player reads "Your name has been struck from the Roll.", everyone else "<name> has been struck from the Roll" (`ui.luau` `systemLine`). | Sections 6 and 11: "freeze and silence" and "all sound ducked", then the shatter, then the line; 40 dB reads as silence while the crack still lands as the duck releases. When deaths overlap, each shatter releases the duck as it cracks (`SfxPool.duck(0, 0)`), so every crack and chime is heard; a second death inside the first one's freeze loses the rest of its silence. | Change `deathDuckDb`, or gate the duck on the local player's own death in `Replication.handlers.EntityDied`. |
| D-036 | Clip `Sfx`/`Voice` events name `sfx.luau` entries as `family.Name`. The placeholder names were mapped to existing entries (swings to `whoosh.*`, dodge, jump, skid and light ground hits to `footsteps.LandSoft`, landings and heavy ground hits to `footsteps.LandHard`, boar and kobold calls to `enemy.Charger*` / `enemy.Brute*`); a Break uses the archetype's Stagger call, not its Death call, because the enemy survives a Break. Clip events that repeated a sound a remote reaction already plays (parry clash, guard block, guard break crack) were removed. | Section 15 lists one asset per line in `sfx.luau`, so each clip sound must point at a registry entry; a death call on a survivable Break would misread as a kill. | Change a clip event's `data.name`, or add a placeholder entry to `sfx.luau` (and the count in `docs/PLACEHOLDERS.md`) first. |
| D-037 | The client paces basic attacks at the server's refill rate: `CharacterController` drops a click that comes sooner than `1 / world.luau anticheat.remoteRates.BasicAttackRequest.perSecond` after the last request it sent (`ActionLogic.basicReady`); it does not buffer it. | Section 17 kicks on sustained abuse, not on fast clicking, and every rate-limit rejection is an anomaly; with the client never over `perSecond`, the burst absorbs about a third of a second of network bunching. | Raise `BasicAttackRequest.perSecond` in `world.luau` (the client gate follows it), or buffer one click instead of dropping it. |
